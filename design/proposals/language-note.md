# 语言提示：从「提示框」到「版本注记」

状态：analysis snapshot（决策前）· 2026-10-24
范围：`BaseLayout` 的 `TranslationNotice` + `LanguageSuggestion`，以及它们在各 locale 页面上的位置。

> 最终选择见 [0004](../decisions/0004-language-note.md)：文章 B、数据/工具/系列索引 A、混合语言索引不加页面级注记。下面的四方向与 D + A 推荐是决策前的分析。

## 现象

在 1440px 下，英文界面里的中文原文页：

| 元素 | 位置 |
| --- | --- |
| 站点页头结束 | y = 64 |
| 提示条 | y = 80–172，宽 749（`max-w-reading`） |
| 正文标题 | y = 244 |
| 提示条到标题 | **72px** |
| 提示条到页头 | 16px |

同一个页面在 D-SIBs 这类全宽页上，提示条仍然只有 749px 宽并居中（x = 346），而正文从 x = 152 开始，宽 1136px。它既不属于页头，也不属于正文的 measure。

这条提示还是一个可堆叠的容器：

- `TranslationNotice` 在 `.space-y-1` 里渲染「未翻译 / 译自 / 原文有更新 / 其他语言版本」；
- `LanguageSuggestion` 在 `notice` 模式下又往同一个容器里 `before()` 一段目标语言的话；
- 在 `/en/d-sibs/` 上，两段话分别是英文的「本页暂无英文版」和中文的「本页有简体中文版本」，而两个链接都指向 `/zh-hans/d-sibs/`；
- 在 `/de/blog/dowse…/` 上，同一个盒子里是德文的「译自英文」和中文的「本页有简体中文版本」；
- `notice` 模式没有关闭按钮，`banner` 模式有——同一个建议，两种行为。

视觉上，它是页面上唯一的灰色填充面 + 2px 左线。Hairline 的其余部分都是白纸、发丝线和字；这个盒子比它引出的标题更重。

## 诊断

1. **归属错误。** 提示是 `BaseLayout` 里 `#main` 的兄弟，而间距由 `main` 自己的 `py-page-top` 决定。提示不能拥有自己的节奏，只能插在页头和正文之间，所以上下不对称。
2. **信息模型错误。** 组件把「事实（原文语言 / 译本 / 过期）」和「提议（读你更偏好的版本）」都当成段落堆在一个容器里。两句话、两个链接、两种语言，没有一个统一的语法。
3. **组件漂移。** `@zone/ui` 有 `Notice`（2px 起始线、一个页面一个），站点却在 `TranslationNotice` 里内联重写了同样的样式；`LanguageSuggestion` 又内联生成第二个表面。
4. **语言策略错误。** 建议是「追加」而不是「替换」；当建议的目标就是原文时，同一件事被说两遍。
5. **宽度硬编码。** 提示自己写死 `max-w-reading`，与页面实际的 measure 无关；全宽页必然错位。

## 新模型

一行，一个语法：

```
[provenance] · [target endonym →]
```

- `Original · 简体中文 →`
- `Aus dem Englischen · 简体中文 →`
- `Translation · original updated · 简体中文 →`

规则：

- **一行。** 不再用 `<p>` 堆叠。备选语言是同一行里的 endonyms，用 `·` 分隔；首选目标在行尾，带箭头。
- **建议替换，不追加。** 服务端先渲染 provenance 和一个默认目标；内联脚本只解析 `navigator.languages` 并把目标换成读者更偏好的 locale。没有「第二段话」。
- **目标等于原文时只留一个动作。** 「读原文」和「切换到原文语言」是同一件事，不出两个链接。
- **说事实，不承诺。** 去掉 “not available in English yet” 的 yet：它承诺了一个没有排期的翻译。
- **不接收 children。** 组件 API 是 `provenance`、`available`、`defaultTarget`、`outdated`；它不负责排版任意文案。
- **默认不关闭。** 一行注记是元数据，不是横幅。如果产品坚持要能收起，只收起 target，保留 provenance，行高不变。
- **宽度归页面。** 提示不设自己的 measure；它继承页头的 measure。

## 四个方向

同一篇文章、同一状态（英文界面 / 简体中文原文 / 读者偏好中文），在真实页面上注入 DOM 得到的视觉稿；这里记录四套的结论（captures 留在本地 review 目录，未入库）。


| | A / Folio | B / Running head | C / Colophon | D / Marginalia |
| --- | --- | --- | --- | --- |
| 位置 | 标题块内，lede 之下 | 标题之上，一道发丝线 | 页级横带，上下发丝线 | ≥1240px 的左侧页边；窄屏回到 A |
| 新增表面 | 无 | 1 条发丝线 | 2 条发丝线 | 1 条短发丝线 |
| 标题位置（1440） | 136（不变） | 154（+18） | 203（+67） | 136（不变） |
| 到达率 | 低 | 高 | 最高 | 中 |
| 全宽数据页 | 可以 | 可以 | 可以 | 不适用 |
| 390px | 好 | 好 | 偏重 | 好（收敛为 A） |
| 风险 | 太安静 | 标题前多一行 | 每个 fallback 页都像封面 | 依赖页边宽度 |

落地后 B 的标题是 156（+20），比视觉稿高 2px；以 `NoteLine` 的实际行高为准。


### A / Folio

`Original · 简体中文 →` 作为标题块元数据的第一行，日期/系列紧随其后。标题仍然是页面的第一件东西；没有新表面，没有宽度，没有 72px 空档。全宽页也对：提示从左边缘开始，而不是缩在 749px 的居中列里。


代价是安静。它更像脚注而不是提示，适合作为所有页面的**保底**，不适合作为唯一的到达方式。

### B / Running head

标题之上一条 `Original` / `简体中文 →` 的 running head，下面一道发丝线。`main` 的 `padding-top` 从 72 降到 40，所以标题只比原来低 18px，却获得了页级的存在感。它把语言变成文章头部的一部分，而不是一个浮在页头上的盒子。


它最稳、最容易解释，也最适合全宽页。唯一的原则冲突是「文章以标题开始」——现在以一行版本信息开始。

### C / Colophon

一条横跨 shell 的刊头：左边是大的 `简体中文` + `ORIGINAL`，右边是 `INTERFACE English → 简体中文`，上下各一条发丝线。它把语言变成页面 front matter，视觉上最有仪式感。


问题是重量：1440 下标题被推到 203，390 下横带占 122px；它适合一个语言索引页或特刊页，不适合每一次 fallback。

### D / Marginalia

≥1240px 时，注记放进标题左侧的页边：一条 168px 的短规则、`ORIGINAL`、`简体中文 →`。标题从 y = 136 开始，一个字都不让。DOM 顺序仍然是标题 → lede → 注记，视觉上却在页边；窄屏自动回到 A 的一行。


它利用的是文章本来就留白的页边，和 section number 用的是同一块地方；不新增界面，只增加一条批注。德文译本 + 中文偏好时，它同样成立：


代价是到达率：它在阅读列之外，靠页头的语言菜单兜底。它适合「提示是补充，不是警报」的产品判断。

## 推荐

> 决策已落在 [0004](../decisions/0004-language-note.md)：文章 B、数据 A、索引无注记。下面是当时的 D + A 备选分析。

**D + A 的响应式组合，作为阅读页的语言注记；全宽数据页用 A。**

- ≥1240px 的阅读页：D，页边注记。
- <1240px 的阅读页：A，lede 下的一行。
- 全宽页（D-SIBs、计算器）：A，放进页面自己的 header/meta 块，继承页面的 measure。
- 没有标题块的归档页：同一行放在列表顶部，对齐 index measure。
- B 作为「需要更高到达率」时的替代；C 留给语言索引 / 特刊页，不做默认。

理由：这四套里，只有 A/D 同时满足三条 Hairline 的硬规则——文章以标题开始、页面只有白纸和发丝线、组件不拥有自己的宽度。D 是 A 在宽屏上的空间表达，不是第二个组件；它们是同一个内容模型的两个位置。B 也很好，但它把一行版本信息放到了标题之前，和第一条原则做交易。

D 用的是 section number 同一块页边，不是第二条侧栏；principle 7 反对的是「第二套界面」，不是一条注记。如果不想这样解释原则，B 是零风险的正确答案。

如果更看重「读者一定要看到」，选 B。如果更看重「页面仍然是文章」，选 D + A。

## 实施（已落地）

见 [0004](../decisions/0004-language-note.md)：`NoteLine`（`runhead` / `inline`）+ `LanguageNote`；文章 B、数据/工具/系列索引 A、混合语言索引无注记；脚本只替换 target；`TranslationNotice`、`LanguageSuggestion`、`Notice` 已删除。

## 不做

- 不再用灰色填充面表达语言状态。
- 不再把「未翻译」和「建议切换」塞进同一个容器。
- 不再给提示写自己的 `max-w-*`。
- 不再用 `prepend` 在 paint 后重排备选语言。
- 不为每个 locale 复制一套布局。

## B 全站审计（2026-10-24 追加）

B 成立有三个前提：页面有一个标题、标题上方没有别的 kicker、整页只有一种内容语言。站点有三类页面不满足：

| 页面 | B 会发生什么 |
| --- | --- |
| 数据页（D-SIBs） | 全宽 1136px 时 `justify-between` 把两端拉开，变成 toolbar；页头已有 `数据观察 / D-SIBs` 的 eyebrow，B 成为第二个 kicker。 |
| 归档 | 没有标题；列表是混合语言，B 的 provenance 只能是 `Interface`，不是 `Original`；列表前多一条 bar，违反「归档从第一条开始」。 |
| Reading / Listening / Books | 页头是自定义 flex，没有共同的 `note` slot；B 会被插到标题下方或需要先统一 PageHeader。 |

另外：

- B 把 `main` 的 top 从 72 降到 40。有 B 的页面和没有 B 的页面，首内容高度相差 18–31px；从一篇纯英文文章跳到一篇 fallback 文章，标题会跳一下。
- B 在每一个内容页都出现，会变成 chrome。它现在吸引注意，是因为它稀有；全站化之后，读者会学会跳过它，就像跳过现在的灰盒子。
- B 没有关闭。它比 A/D 更抢眼，但没有拒绝的出口；旧的 banner 有。
- B 的 target 链接在 h1 之前进入 DOM，阅读顺序是「语言提议 → 标题」。不是大问题，但 A/D 把标题留在前面。

结论：**B 是文章页的最佳版式，不是全站唯一版式。** 全站可以共享 B 的**语法**（`provenance · target →`），但不必共享 B 的**版式**：

- 文章 / 系列文章：B。
- 数据 / 工具页：A（lede 下，跟随页面的 measure）。
- 归档 / Reading / Listening / Books：页头的语言菜单就是开关，不加页面级注记。若一定要一条可见的提示，用 A 放在列表顶部，并接受「归档从第一条开始」这条规则被改写。


如果仍要全站 B，需要先做四个决定：统一所有页面的 header/note slot；为全宽页定义 B-wide（左对齐或并入 eyebrow，而不是 `justify-between`）；为索引页定义 `Interface` 这一种 provenance；决定 page top 是 40 还是 72、以及 B 是否可关闭。这四件事做完，B 就不再是一个版式，而是一个 placement 家族。
